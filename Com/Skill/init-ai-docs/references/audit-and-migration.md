# 冲突审计与迁移

用于只读审计、拆分、去重及大范围文档整理。局部更新只应用相关核对项。

## 先建立问题证据

| 类别 | 判断依据 | 处理 |
|---|---|---|
| 矛盾 | 同一对象、同一条件下结论互斥 | 记录双方位置，查已确认规则及相关实现 |
| 过期 | 旧说明与已有新规则或当前入口不一致 | 核实后更新原条目，必要时归档历史 |
| 重复 | 两处维护同一完整规则 | 指定主文档，其他位置摘要加链接 |
| 分类错误 | 已落地事实放进未知项，或历史混入当前策略 | 移到正确职责，不改变内容可信度 |
| 导航/体量 | 断链、入口不可达、超限、过长段落 | 修路由或按业务边界拆分 |

区分版本、平台、生命周期和异常分支，避免把不同条件下的行为误判为矛盾。不能仅按文件新旧、所在位置、出现顺序或“最新规则”字样决定优先级。

源码可证明当前实现，实际响应可证明本次服务器行为，二者都不自动替代用户已确认的业务约定。无法判定的冲突继续列出双方证据和需要确认的点，只暂停依赖该结论的修改。

## 安全迁移

1. 检查当前 diff，保存受影响文档的修改前快照或使用可证明对应当前内容的 Git 基线；有未提交修改时不能直接用 HEAD 代替现场文件。
2. 建临时清单，至少包含原位置/条目、目标位置、处理方式及依据。长条目拆成多处时记录全部去向；该清单默认不成为常驻业务文档。
3. 先建立承接专题，再更新原入口。未核实的信息保留 UNKNOWN，不能用补全语句填空。
4. 合并条目时逐项检查字段与数值、单位、条件、例外、错误处理、生命周期、资源绑定、精确文案和验收状态。保留原文独有细节；不能仅凭同一类名、token 覆盖率或文本相似度删除。
5. 对每项删除给出被替代的主条目或明确过期依据。未知项只能在证据足以解决时移除；迁移本身不解决未知项。
6. 更新正反向链接及必要锚点。保留原模块文件作为入口，除非已明确授权删除或改名。
7. 复核清单的每个原条目均有结果，并抽查完整调用链和跨域规则。机械匹配通过不等于语义完整。

## 只读脚本

需要 Python 3.10+，仅使用标准库。从本技能目录执行，或使用脚本绝对路径：

```text
python scripts/audit_docs.py /project/Doc
python scripts/audit_docs.py /project/Doc --scope Modules/chat.md --scope Modules/backend.md
python scripts/audit_docs.py /project/Doc --entry AI_Understanding.md --entry OtherIndex.md --json
python scripts/audit_docs.py /project/Doc --entry-kib 10 --module-kib 5 --topic-kib 28 --long-line 600
```

- 默认递归审计 Markdown，排除 ChangeLog、Decisions、隐藏目录和符号链接。`--include-cold` 显式包含冷文档；它们不参与体量与孤立专题告警。
- `--scope` 是相对文档根的精确文件路径，可重复。局部模式只读取这些文件，不计算全库导航可达性。入口默认 `AI_Understanding.md`，多个 `--entry` 表示多个有效根入口。
- 总入口用 entry 预算；`Modules/x.md` 存在同名子目录且目录含 Markdown 时按已拆分模块入口预算；其他文件按专题预算。非此布局的分类需要人工判断，脚本不推测职责。
- 报告包含字节数、超限、长行、相对链接缺失、从入口沿 Markdown 链接不可达的专题，以及去除空白后完全相同的长段落候选。`--duplicate-chars` 默认 160，可调整；不会按相似度自动合并。
- `--json` 输出完整 JSON 到 stdout；默认文本报告仅展示前 `--limit` 条详情及各类总数。不产生报告文件，不修改被审计目录，不访问网络或读取图片内容。
- 支持常见行内链接、引用式链接和图片文件路径存在性检查；导航只使用非图片链接。忽略 fenced code 和行内代码。只检查文件目标存在，不验证标题锚点、代码行号、HTML 链接、复杂 Markdown 方言或远端地址；用这些形式维护的导航可能被列为不可达候选，须人工确认。
- 退出码 0：扫描完成且无机械错误（仍可能有体量、长行、孤立或重复候选）；1：编码、断链、读取错误或缺失入口；2：参数错误。退出码不代表业务语义或运行验收。

## 验收与汇报

先确认原文去向和冲突结论，再检查 UTF-8、链接、导航、体量、旧规则残留及最终 diff。只读审计输出位置、影响与证据，不写 ChangeLog；修改任务按项目规则记录实际变更。

汇报入口与最大专题体量、处理过的冲突和剩余问题；不要把字节下降比例说成 token 节省比例。说明本次验证实际覆盖范围，保留运行和服务器联调限制。
