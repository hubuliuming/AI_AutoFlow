# Cocos 代码规范

## 代码结构清晰

- 写入代码时必须保持职责边界清晰
- 不允许把多个职责堆在同一个脚本中
- 当实现包含多个独立职责、流程阶段或可复用能力时，应适当拆分为多个脚本
- 拆分脚本必须服务于已确认方案和现有结构，不得借机重构系统或扩展无关模块
- 新增 `Component`、服务类、工具类或配置文件前，必须确认它们属于已确认方案范围

## 失败暴露优先

- 禁止为了“防止报错”添加防御式冗余校验
- 必需依赖缺失应让运行时自然报错，便于发现资源绑定、初始化顺序或调用链问题
- 不允许用 `null` 校验吞掉必需依赖错误
- 不允许用 `find`、`director.getScene()`、`getChildByName`、递归节点搜索等查找 API 兜底必需节点
- 不允许用临时动态创建节点、组件、资源、空对象或默认配置兜底必需依赖
- 属性检查器、Prefab、Scene、文档或已确认方案定义为必需的字段，默认视为必须存在
- 只有外部输入、用户输入、存档数据、网络数据、异步加载结果、平台 API 返回值、远端配置或文档明确可选的对象，才属于必须校验范围
- 若发现必需依赖可能为空，应阻断并要求确认绑定、资源引用或调用链，不得自行补兜底逻辑

---

## 编写代码规范

适用范围：会进入 Cocos Preview、Web、小游戏或原生正式构建产物的 TypeScript / JavaScript 运行时代码。

### 性能优先与保护性代码规则

- 在保证行为正确、职责边界清晰和已确认需求成立的前提下，性能优先，优先选择更少分配、更少遍历、更少查找和更低调用开销的实现
- 禁止为未经证实的异常路径堆叠 `null` 判断、重复校验、无意义的 `try/catch`、默认值兜底、对象复制或集合转换
- 保护性检查只用于外部输入、文档明确可选的对象或已经证实的风险，并应在责任边界统一处理，避免在调用链各层重复防护
- 性能优化不得牺牲正确性或改变已确认行为；无法确认风险时应先暴露问题并请求确认，不得自行增加兜底代码

### 非数组可迭代对象转换规则

- 禁止使用数组展开语法把 `Set`、`Map`、`Map.entries()`、`Map.keys()`、`Map.values()`、生成器或其他非数组可迭代对象转换为数组
- 禁止写法包括 `[...new Set(values)]`、`[...map.entries()]`、`[...map.keys()]`、`[...map.values()]`
- 必须分别使用 `Array.from(new Set(values))`、`Array.from(map.entries())`、`Array.from(map.keys())`、`Array.from(map.values())`
- 对遍历期间会删除或修改的 `Map` / `Set`，必须先通过 `Array.from()` 建立稳定条目快照，再遍历并修改原集合
- 原生数组的展开不受本规则限制
