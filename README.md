# AI_AutoFlow

AI_AutoFlow 是一个围绕 Unity 项目协作、AI 文档理解和本地 Skill 管理组织的工程仓库。

当前仓库已明确的重点是：通过项目文档记录真实状态，通过确认后的方案驱动修改，并在执行后把真实改动同步回文档。Unity 运行时架构、玩法、构建流程等尚未在现有文档中明确记录的内容，当前视为 `UNKNOWN`。

## 适用对象

本仓库适合以下使用者：

- 需要了解项目当前结构和协作方式的开发者。
- 需要维护项目文档、Skill 或 Unity 侧规则的维护者。
- 需要基于项目文档执行任务的 AI 协作代理。

## 使用流程

1. 先阅读本 README，了解仓库用途、目录和协作流程。
2. 查看 `Doc/AI_Understanding.md`，确认当前已记录的项目事实、未知项和维护策略。
3. 如需让 AI 修改项目，先提出目标，由 AI 根据项目文档生成方案。
4. 确认方案后再执行修改。
5. 修改完成后，将真实发生的改动同步回相关项目文档。

未在项目文档中明确记录的信息，不应作为执行依据。

## 目录结构

- `Doc/`：AI 面向的项目文档，当前核心入口是 `Doc/AI_Understanding.md`。
- `Com/Skill/`：项目内 Codex Skill。
- `Unity/`：Unity 侧项目区域与 harness 规则文档。
- `AGENTS.md`：根目录 Codex 协作规则。
- `LICENSE`：许可证文件。

## 协作约定

本项目采用受控协作流程：

1. 先生成方案。
2. 等待用户确认方案。
3. 基于已确认方案执行。
4. 执行后同步更新项目文档。

默认不在未确认方案的情况下修改代码、资源结构或项目规则。执行后的文档更新只记录真实发生的改动，不写假设、建议或未来计划。

## 维护者注意

每当修改 `Com/Skill/` 下任意 Skill 内容时，必须同步修改 Codex 客户端侧对应 Skill：

- 默认目标：`C:\Users\用户\.codex\skills\<skill-name>\`
- 同步范围：`SKILL.md`、`agents/openai.yaml`，以及该 Skill 下实际存在的 `scripts/`、`references/`、`assets/` 等资源。

如果客户端侧 Skill 路径不存在、同步目标不明确、结构不兼容，或写入目标需要额外权限且未获确认，必须停止并输出阻断原因和需要确认的信息。
